## 关于更新和上传：
- [ ! ] 每次上传时请先拉取最新代码，本地合并完成后再上传，以保证你上传的内容最新的
- [ ! ] 尽量不要多人同时改同一个部分

- 每次上传时请先修改项目主目录的 *README.md* （即本文件）
    - 修改日期，日期即为你提交时的日期
    - 主版本号，根据规则修改：
        - 主版本号A.B.C的含义：A-重大更新（大量更改或重写、整体结构更改） | B-普通更新 | C-小更新（修小BUG等等）
        - 更改方式：本位+1、后位清零，按优先级最高的来
        - 例子：原本1.0.2 -> 重大更新，增加了一些功能并改了一些小BUG -> 2.0.0（重大更新优先级最高，A+1，后位都清零）

- 更新日志的规则：
    - 在主目录下的 *version* 文件夹中，创建一个 *最新版本号.md* 的文件
    - 写入更新日期
    - 写入此次更新的具体内容

- 子部分的修改方式：
    - 每个子部分放在对应子文件夹中，包括源代码、必要资源和一份 *README.md*
    - 如果你修改了某个子部分，则需要修改 *README.md* 中的日期，并根据具体的修改，编辑 *README.md* 的内容

- 注意事项：
    - 不要随意修改别人部分的代码，特别是头文件（有问题叫对应的人改）
    - 如果有新增加的子部分，请按照结构创建
    - *.md* 文件的书写格式尽量符合规范且统一
    - 子部分如果只是修了BUG则只需要修改子 *README.md* 的日期，但是更新日志仍需要说明修复了什么BUG之类的
