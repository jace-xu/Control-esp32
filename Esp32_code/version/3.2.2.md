# 2026.6.10

## 更新内容
- 修复了一些发送指令后未等待的问题
- 更新了一些参数，包括放置时的位置和先后顺序等
- 放置阶段（X 键）重写为**纯手动逐步确认**流程，并按「流程在 TaskCoordinator、其他类只提供动作」
  的架构移入 **TaskCoordinator**，**删除视觉对准与颜色队列**：
    - 流程：按 X 开爪转到出料口（首次自动 `compact()` 压紧）→ 顶料 `dispense()` → 合爪领取 →
      r轴前伸到头 + `notifyPicked()` 送下一块 → 转180°+下降 → **手动 d-pad 瞄准**（左右=角度5，上下=前后7）→
      下降到底 → 开爪放置 → 回升回出料口 → 仓非空续下一块，空则结束。
    - 每一步靠 **X 键上升沿**推进（人确认上一步到位），不做位置轮询自动判定；加步进锁防手快。
    - 手动瞄准用 `setAngleForwardPosition` 打包角度+前后为一条长命令，单次总线事务、满足 ~2ms 间隔。
- **TaskCoordinator** 接管全流程调度：
    - 构造改为注入 *ArmControl* / *ArmSequence* / *TrayControl*；`update` 扩展 d-pad 参数。
    - 每帧推进 `tray->update()`；`isActive()` / `stop()` 并入物料盘忙状态与急停。
    - 阶段1 入仓握手：用 `arm_seq->isActive()` 边沿编排 `prepareStore`（启动）/ `store`（结束，count+1）/
      `tray->stop()`（中止），count 作为阶段2 `dispense()` 出料的前提。
- **ArmSequence** 退化为阶段1 动作提供者：移除 *PlaceSequence* / *ColorQueue* 依赖与记色逻辑，
  保留视觉对准+夹取+收臂；不再处理 X 键。
- **PlaceSequence** 退役（不再被 include/使用，文件保留作历史参考）。
- 修复 **TrayControl** `kTightenTable` 链接错误：补 `static constexpr` 数组的类外定义
  （`dispense`/`compact` 被实际调用后 ODR-use，C++14 需要存储定义）。
- main.cpp：转发 d-pad 给协调器，调整 TaskCoordinator 构造参数。

## 注意事项
- [ ! ] 放置流程所有位置/角度为占位常量，逻辑未实车验证，首跑前需现场校准（撞机/夹空风险）。
- [ ! ] 阶段2 出料要求物料盘 count>0：须先经阶段1 入仓产生数量，否则按 X 提示队空不启动。
