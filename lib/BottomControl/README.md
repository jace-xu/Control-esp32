## 这是底盘控制类，集成了底部四个电机的控制
- 该类只有一个全局单例
    - 使用指针或引用接收 *BottomControl::get_instance()* 返回的对全局单例的引用

- 底盘的控制
    - 直接控制：
        - 调用 *某个操作(目标速度参数)* 即可直接控制
    - 缓存命令
        - 先调用 *threading_lock()* 为线程上锁（单线程无需考虑）
        - 调用 *append_某个操作_command(目标速度参数)* 将四个电机的控制命令暂存至长缓冲区
        - 继续添加其他的命令至长缓冲区
        - 调用 *send_long_command()* 将长命令发送
        - 调用 *threading_unlock()* 将线程解锁（单线程无需考虑）
    - 调用 *clear_command()* 可以清空长缓冲区的内容，但一般无需使用

- 线程锁
    - 底盘类的线程锁接口会直接调用串口对象的线程锁，与直接调用 *ControlSerial::thread_lock()* 和 *ControlSerial::thread_unlock()* 等效
    - 上锁后，如果别的线程同时调用了串口对象，则别的线程会进入等待，直到本线程解锁后才会释放使用权
    - 线程锁的 *threading_lock()* 和 *threading_unlock()* **必须配对使用**
        - [ ! ] 如果只上锁未解锁，别的线程调用了该对象后将会永久阻塞
        - [ ! ] 如果没上锁直接解锁了，程序可能会直接崩溃，或产生意义不明的BUG

- 信息读取
    - 功能尚未添加

- 注意事项
    - [ ! ] 如果没有初始化，则无法使用串口对象（线程可使用串口对象时直接返回）
    - 无论是否多线程，只执行一步操作的话不需要上锁（函数内自带线程锁）
    - 调用底盘的缓存命令操作时，会先清空长缓存区，因此地盘操作需要作为最先添加的指令（如果先添加了别的指令，会丢失）
    - 长缓冲最多可容纳7条最长的电机消息(七个电机都是位置模式时)
    - 使用长命令时，不建议同个电机执行多个操作
    - 解锁线程后别的线程就可以修改缓冲区了，如果你在解锁前没有发送，命令可能会丢失
